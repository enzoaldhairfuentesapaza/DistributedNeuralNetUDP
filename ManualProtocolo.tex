\section{Descripción General}

El objetivo del proyecto es implementar un sistema de Red Neuronal Distribuida (DNN) donde el aprendizaje se reparte entre varias computadoras o terminales y el servidor principal combina los resultados mediante el promedio de las matrices de pesos.

\begin{itemize}
\item La red neuronal se define y entrena en Python.
\item La ejecución principal se inicia desde un archivo \texttt{.py}.
\item Python llama a una biblioteca distribuida en C++ mediante \texttt{pybind11}.
\item La biblioteca C++ implementa la comunicación UDP y el protocolo RDT.
\item La comunicación entre nodos utiliza UDP.
\item La confiabilidad se implementa manualmente mediante un protocolo RDT (Reliable Data Transfer) basado en Go-Back-N puro con ACK acumulativo.
\end{itemize}

La arquitectura del sistema está compuesta por:

\begin{itemize}
\item Un servidor principal (Main Server / Master)
\item Diez servidores trabajadores (Workers)
\item Un programa o módulo de distribución de datos invocado por el servidor principal
\end{itemize}

El servidor principal divide el dataset en 11 partes iguales: una parte queda en el master y las otras 10 partes se envían a los workers. Luego distribuye las matrices de pesos de la red, recibe las matrices entrenadas por cada nodo y actualiza su red neuronal principal calculando el promedio elemento a elemento.

\section{Transferencia Confiable de Datos (RDT)}

UDP no garantiza:

\begin{itemize}
\item Entrega de paquetes
\item Orden correcto
\item Integridad
\item Protección contra duplicados
\end{itemize}

Por esta razón se implementará un protocolo RDT sobre UDP utilizando Go-Back-N.

\section{Características del Protocolo RDT}

El protocolo implementará el mecanismo Go-Back-N sobre UDP.
Go-Back-N permitirá enviar múltiples paquetes consecutivos sin esperar una confirmación inmediata por cada uno de ellos.
El protocolo no utilizará NACK explícitos; ante paquetes corruptos, duplicados o fuera de orden, el receptor reenviará el último ACK acumulativo válido y el emisor recuperará la transferencia mediante timeout y retransmisión Go-Back-N.

\begin{table}[h]
\centering
\begin{tabular}{|l|p{9cm}|}
\hline
Característica & Descripción \\
\hline
ACK acumulativo & Confirma el último paquete recibido correctamente en orden \\
\hline
Ventana deslizante & Permite mantener varios paquetes en tránsito simultáneamente \\
\hline
Número de secuencia & Detecta pérdidas, duplicados y mantiene el orden \\
\hline
Timeout & Detecta pérdida de paquetes o ACKs \\
\hline
Retransmisión Go-Back-N & Retransmite todos los paquetes desde el paquete posterior al último ACK confirmado \\
\hline
CRC32 & Detecta corrupción tanto en el encabezado como en el payload \\
\hline
Recepción en orden & El receptor solo acepta el paquete esperado y descarta paquetes fuera de orden \\
\hline
\end{tabular}
\end{table}

Si un paquete o conjunto de paquetes supera el máximo de reintentos definido, la transferencia se considerará fallida y será cancelada.

\subsection{Descripción de campos}

\begin{itemize}

\item \textbf{Tipo de paquete:} Identifica si el paquete corresponde a DATA, ACK, START o END.

\item \textbf{Número de secuencia:} Identifica el orden lógico del paquete dentro de la transferencia. Permite detectar pérdidas, duplicados y mantener el orden correcto.

\item \textbf{Número ACK:} Indica el último número de secuencia recibido correctamente y en orden. Este campo se utiliza principalmente en paquetes ACK. Por ejemplo, si el receptor recibió correctamente los paquetes 0, 1 y 2, enviará un ACK con valor 2.

\item \textbf{ID de matriz:} Identifica la matriz de pesos asociada al paquete. Cuando el paquete transporta una partición del dataset, este campo identifica la partición.

\item \textbf{Número de fragmento:} Indica la posición del fragmento dentro de la matriz.

\item \textbf{Total de fragmentos:} Permite reconstruir completamente la matriz original.

\item \textbf{Tipo de contenido:} Define si el payload contiene una partición del dataset, matrices de pesos iniciales, matrices entrenadas o datos de control.

\item \textbf{Tamaño útil del payload:} Indica cuántos bytes válidos contiene el payload. Este valor no puede superar 484 bytes.

\item \textbf{CRC32:} Código utilizado para detectar corrupción en el encabezado y en el payload. Para calcularlo, el campo CRC32 se coloca temporalmente en cero y luego se calcula el CRC32 sobre todo el encabezado más el payload válido.

\item \textbf{Payload:} Contiene fragmentos serializados de matrices.

\end{itemize}

\section{Integridad de Paquetes}

Cada paquete incluirá un valor CRC32 calculado sobre el encabezado y el payload válido del paquete.

Para realizar el cálculo, el campo CRC32 se coloca temporalmente en cero. Luego se calcula el CRC32 sobre:

\[
\text{CRC32} = CRC32(\text{header con CRC32 = 0} + \text{payload válido})
\]

Esto permite detectar corrupción no solo en los datos de la matriz, sino también en campos críticos como el tipo de paquete, número de secuencia, número ACK, ID de matriz, número de fragmento, total de fragmentos, tipo de contenido y tamaño útil del payload.

El receptor recalculará el CRC32 utilizando el mismo procedimiento y lo comparará con el valor recibido.

\subsection{Si el CRC32 coincide}

\begin{itemize}
\item El paquete se considera íntegro.
\item El receptor verifica si el número de secuencia corresponde al paquete esperado.
\item Si el paquete es el esperado, se acepta y se actualiza el último número de secuencia recibido correctamente en orden.
\item Se envía un ACK acumulativo indicando el último paquete recibido correctamente en orden.
\end{itemize}

\subsection{Si el CRC32 falla}

\begin{itemize}
\item El paquete se considera corrupto.
\item El paquete completo se descarta.
\item No se actualiza el número de secuencia esperado.
\item El receptor reenvía el ACK acumulativo del último paquete recibido correctamente en orden.
\item No se envía NACK, porque el protocolo utiliza Go-Back-N puro.
\end{itemize}

\section{Números de Secuencia, ACK y Ventana}

Cada paquete DATA tendrá un número de secuencia único dentro de la transferencia.

El protocolo utilizará una ventana deslizante Go-Back-N de tamaño configurable. El valor inicial de la ventana será de 8 paquetes.

La ventana permitirá mantener múltiples paquetes en tránsito simultáneamente.

El campo ACK tendrá semántica acumulativa:

\begin{itemize}
\item Un ACK con valor $n$ indica que todos los paquetes desde el inicio hasta el paquete $n$ fueron recibidos correctamente y en orden.
\item Si el receptor espera el paquete $k$ pero recibe un paquete distinto, lo descarta y vuelve a enviar el ACK del último paquete válido en orden.
\item Si se pierde un ACK, el emisor podrá continuar si recibe un ACK posterior con un número mayor.
\end{itemize}

Los números de secuencia permitirán:

\begin{itemize}
\item Detectar paquetes duplicados
\item Detectar paquetes perdidos
\item Mantener el orden correcto
\item Controlar retransmisiones
\item Implementar ACK acumulativos
\end{itemize}

\section{Timeouts y Reintentos}

El protocolo utilizará un timeout inicial de 500 ms.

Si el emisor no recibe un ACK válido antes de que expire el timeout, retransmitirá todos los paquetes pendientes desde el paquete posterior al último ACK confirmado.

El número máximo de reintentos será 5. Si después de 5 reintentos no se recibe confirmación, la transferencia se marcará como fallida y será cancelada.

\section{Secuencia de Comunicación}

La transferencia confiable seguirá el siguiente flujo:

\begin{enumerate}

\item El servidor principal envía un paquete START.

\item El worker responde con ACK.

\item El servidor principal comienza el envío continuo de paquetes DATA dentro de la ventana Go-Back-N.

\item El worker verifica el CRC32 calculado sobre encabezado y payload.

\item Si el CRC32 es válido, el worker verifica el número de secuencia.

\item Si el paquete recibido es exactamente el paquete esperado:
\begin{itemize}
\item El worker acepta el paquete.
\item Actualiza el último número de secuencia recibido correctamente en orden.
\item Envía un ACK acumulativo con ese número de secuencia.
\end{itemize}

\item Si el paquete recibido está duplicado o fuera de orden:
\begin{itemize}
\item El worker descarta el paquete.
\item El worker reenvía un ACK acumulativo con el último número de secuencia recibido correctamente en orden.
\end{itemize}

\item Si un paquete llega corrupto:
\begin{itemize}
\item El worker descarta el paquete completo.
\item El worker no avanza su número de secuencia esperado.
\item El worker puede reenviar el último ACK acumulativo válido.
\end{itemize}

\item Si ocurre timeout:
\begin{itemize}
\item El servidor retransmite todos los paquetes desde el paquete posterior al último ACK confirmado.
\end{itemize}

\item Si se supera el máximo de reintentos:
\begin{itemize}
\item El servidor cancela la transferencia.
\item El estado de la transferencia pasa a FAILED.
\end{itemize}

\item Cuando todos los fragmentos son enviados y confirmados:
\begin{itemize}
\item El servidor envía END.
\item El worker responde con ACK final.
\end{itemize}

\end{enumerate}

\section{Distribución del Dataset y de Pesos}

El servidor principal coordinará la distribución del aprendizaje. Para ello invocará un programa o módulo de distribución que dividirá el dataset en 11 partes iguales.

\begin{itemize}
\item La partición 0 será usada por el master.
\item Las particiones 1 a 10 serán enviadas a los workers 1 a 10.
\item Los workers podrán ejecutarse en computadoras distintas o en terminales separadas.
\end{itemize}

El forward pass inicial se realizará únicamente en el master. Después, el master ejecutará backpropagation para generar o actualizar las matrices de pesos de las capas ocultas.

La red neuronal tendrá 4 capas ocultas de 200 neuronas. Por lo tanto, el master distribuirá 4 matrices completas de pesos:

\[
W_1,\; W_2,\; W_3,\; W_4
\]

Cada matriz tendrá tamaño 200x200 y será enviada completa a cada worker. Los workers no recibirán bloques de filas de una matriz, sino las 4 matrices completas para mantener una copia equivalente de la red neuronal.

\section{Serialización de Datos y Matrices}

Las particiones del dataset y las matrices de pesos serán serializadas utilizando arreglos continuos de tipo float32 en formato little-endian.

Python enviará arreglos NumPy hacia C++ mediante pybind11.

C++ convertirá los datos y las matrices en secuencias binarias para fragmentarlas en paquetes UDP de hasta 512 bytes.

Cada worker reconstruirá los fragmentos recibidos en orden antes de iniciar su entrenamiento local.

\section{Flujo General del Sistema}

\begin{enumerate}

\item Python carga el dataset y define la red neuronal.
\item El servidor principal invoca el programa de distribución del dataset.
\item El dataset se divide en 11 partes iguales.
\item El master conserva una partición y envía las otras 10 particiones a los workers.
\item El master ejecuta el forward pass inicial.
\item El master ejecuta backpropagation y obtiene las 4 matrices de pesos de las capas ocultas.
\item Python entrega esas matrices a la biblioteca C++ mediante pybind11.
\item C++ serializa y transmite las particiones y matrices usando UDP con Go-Back-N.
\item Cada worker reconstruye su partición y las 4 matrices completas.
\item Cada worker entrena su red neuronal local durante 1 época con batch size 1.
\item Cada worker llama a la biblioteca C++ para enviar sus 4 matrices entrenadas al master.
\item El master combina sus propias matrices con las matrices recibidas de los 10 workers.
\item El master calcula el promedio elemento a elemento para cada una de las 4 matrices.
\item Python actualiza la red neuronal principal con las matrices promediadas.

\end{enumerate}

\section{Promedio de Matrices de Pesos}

La operación principal de combinación será el promedio de pesos por capa. Para cada capa oculta $l$, el master calculará:

\[
W_l^{final} =
\frac{
W_l^{master} + \sum_{i=1}^{10} W_l^{worker_i}
}{11}
\]

Este promedio se realizará para las 4 matrices de pesos:

\[
l \in \{1, 2, 3, 4\}
\]

El resultado será una nueva versión de las matrices de la red neuronal principal del master.

Ejemplo:

\section{Conclusión}

El proyecto implementa un sistema de entrenamiento distribuido de una red neuronal utilizando UDP y una capa RDT desarrollada manualmente.

La arquitectura combina Python para la definición y entrenamiento de la red neuronal con una biblioteca C++ encargada de la comunicación confiable sobre UDP.

La confiabilidad será implementada mediante:

\begin{itemize}
\item Go-Back-N puro
\item Ventanas deslizantes
\item ACK acumulativos
\item CRC32 aplicado sobre encabezado y payload
\item Timeouts
\item Retransmisiones automáticas
\item Máximo de reintentos
\item Estados definidos para emisor y receptor
\end{itemize}

El sistema permitirá distribuir el dataset entre 1 master y 10 workers, entrenar copias equivalentes de la red neuronal y combinar las matrices de pesos mediante promedio elemento a elemento.

La arquitectura propuesta servirá como base para futuras extensiones orientadas a entrenamiento paralelo de redes neuronales.
